## 2. 缺陷修复设计

### B1　扩展页开关卡死（P0）

**现象**：在「扩展」页切换“启用自动备份 / 启用移动端只读”等开关，界面卡死；重启应用后开关已生效。

**根因（已定位）**：
1. `src-tauri/src/commands.rs` 的 `set_config` 是**同步命令**，在函数体内直接调用
   `crate::restart_mobile(&app)` 与 `crate::restart_git_autocommit(&app)`（见该文件 `set_config` 尾部）。
2. `src-tauri/src/lib.rs::restart_mobile` 先 `server.stop()`，而 `mobile.rs::MobileServer::stop`
   内部 `self.server.unblock()` 后**同步 `h.join()`**（阻塞等待服务线程退出）；
3. `restart_mobile` / `restart_git_autocommit` 的锁获取、`tiny_http` 绑定、旧线程 join 都在
   `set_config` 返回之前同步完成，阻塞了承载 IPC 的线程 → UI 卡死。
4. 配置本身在 `storage.save_config(&config)` 已先行落盘（`set_config` 中位于重启调用之前），
   所以“重启后生效”与现象完全吻合。

**目标行为**：开关即时反馈、不卡 UI；服务在后台重启；失败通过 Toast/事件提示，不阻塞。

**实现方案**：
- 拆分 `set_config`：先落盘 `save_config` 并返回新 Config；将
  `register_hotkey` / `restart_mobile` / `restart_git_autocommit` 移出同步路径，
  改为 `tauri::async_runtime::spawn` / `std::thread::spawn` 后台执行。
- `MobileServer::stop` 改为**非阻塞**：用 `AtomicBool` 停机标志 + `unblock()`，不再同步 `join`；
  线程退出后自行回收（或 `join` 放后台任务）。
- 保留 `mobile-start-error` 事件提示（已有），并新增 `git-backup-error` 事件或在重启失败时返回错误。
- 前端 `ExtensionsPage` 的 `save()` 不再 `await` 服务重启，仅 `await saveConfig`，避免等待副作用。

**回归点**：见 §7 的 B1 项。

### B2　移动端只读页面白屏（P0）

**现象**：开启移动端只读后，手机访问 `http://<IP>:8731` 页面空白无内容。

**根因（已定位 + 需复现确认）**：
- `mobile.rs` 的 `PAGE_HTML` 中，所有内容均由内联脚本末尾无条件 `renderCandidates()` →
  `fetch('/api/candidates')` 成功后注入 `#content`。
- 页面无任何**加载中/错误/空态的可见兜底**：若该 fetch 失败（服务线程内 `load_snapshot`→`load_all`
  或 `compute_candidates` 抛错返回 500、或手机与电脑不同网段、或系统防火墙拦截），`#app`/`#login`
  均处于 `hidden`，`fail()` 只写回 `#content`，最终呈现为空白。
- 另：`load_snapshot` 在每次请求时**新建一个 Storage** 读取数据目录，若与主进程写回并发、或目录不可读，
  同样会落到 500 → 白屏，且用户无任何可读错误。

**目标行为**：访问即有明显反馈（加载中 → 内容 / 明确错误文案 / 空态）；接口异常可见可定位。

**实现方案**：
- 在 `PAGE_HTML` 增加：
  - 首屏默认显示“加载中…”（去掉 `#app` 依赖 fetch 成功才显示的逻辑）；
  - `fail()` 输出**醒目的错误信息**（含 `status` 与 `message`），不依赖隐藏元素；
  - 空态文案（无候选/无事件/无日常/无归档）已部分具备，需确认在候选为空时也可见。
- 后端 `mobile.rs` 增加 `GET /api/health`：返回 `{ok:true, time, version}`，不鉴权、不读数据目录；
  供前端自检“服务可达”。
- `route_api` 中 `load_snapshot` / `compute_candidates` 的错误改为**结构化 JSON**（已有 `{"error"}`），
  并确保非 200 时前端能展示。
- 文档与设置页明确提示：手机需与电脑**同一局域网网段**，并检查 Windows 防火墙放行 8731 端口。
- （复现项）在真实手机 + 真实 LAN IP 上验证，必要时在 `mobile.rs` 记录请求日志辅助定位。

**回归点**：见 §7 的 B2 项。

### B3　移动端访问地址显示真实 IP（P1）

**根因**：`src/pages/ExtensionsPage.tsx::MobileTab` 第 736 行硬编码
`http://&lt;本机局域网IP&gt;:{mobile.port}`；`MobileStatus`（`commands.rs::MobileStatus`）不含地址字段。

**目标行为**：服务运行时，直接显示可点击/可复制的真实访问地址，如 `http://192.168.1.23:8731`。

**实现方案**：
- 新增后端命令 `get_lan_addresses()`：枚举本机 IPv4 局域网地址（跳过回环/虚拟网卡），
  返回 `Vec<{name, ip}>`（可用 `local-ip-address` crate，或 `std::net::UdpSocket` connect 探测 + 接口枚举）。
- `MobileStatus` 增加 `addresses: Vec<String>`（由 `mobile_status_cmd` 填充）。
- `MobileTab` 显示多个地址（多个网卡时），每个地址旁提供“复制”按钮；未运行时显示占位提示。

**回归点**：见 §7 的 B3 项。

### B4　深色主题输入框对比度（P1）

**根因**：`src/components/Drawer.tsx` 的 `inputCls`（第 19–20 行）只定义了
`border/focus/outline`，**未定义背景与文字颜色**，深色主题下继承暗色文字叠在暗色背景上，导致看不清。
`SettingsPage.tsx` / `ExtensionsPage.tsx` 的个别 `select/input` 也存在类似缺色问题。

**目标行为**：深色主题下所有输入类控件文字清晰可读（浅色文字 + 深色背景），placeholder 可见。

**实现方案**：
- 统一补齐输入类控件的 `bg-white dark:bg-slate-800 text-gray-800 dark:text-slate-100`
  与 `placeholder:text-gray-400 dark:placeholder:text-slate-500`；
- 建议抽取一个共享 `inputClass` 常量（`src/lib/` 或 `styles.css` 的 `@layer components`），
  替换 Drawer/Settings/Extensions 中散落的样式串，避免再次遗漏；
- 全量走查 `text-*` 未配 `dark:text-*` 的控件（搜索、归档、事件/日常/浮动列表页）。

**回归点**：见 §7 的 B4 项。

### B5　日常同窗口重复归档（P0）

**根因**：
1. `src-tauri/core/src/candidates.rs` 层级 2（当前窗口内日常，第 160–179 行）**未判断 `done`**，
   仅层级 3（第 180 行 `else if !done`）过滤了已完成；因此日常在窗口内点“完成”后仍作为候选出现。
2. `commands.rs::complete_candidate` 对 `Routine` 来源**不写任何完成标记**（只对 Event/Task 标记
   `status/completedAt`），且 `persist_archive` 每次都会 `push` 一条新归档，
   于是重复点击“完成”就会在时间轴与归档中产生多条同源记录。

**目标行为**：日常在“今天”完成一次后，当日不再进入候选、不可再次归档；时间轴只显示一次已完成。

**实现方案**（三处叠加，防止回归）：
1. `candidates.rs`：层级 2 增加 `if !done` 过滤（与层级 3 一致）；
2. `complete_candidate`：对 Routine 来源，在写入归档前检查**当日是否已存在同 `sourceId` 的归档**，
   若已存在则拒绝重复归档（返回错误或幂等返回已有条目）；
3. `persist_archive`：可选加**当日同 `source + sourceId` 去重**保护（`day.entries.retain` 已有按 id 去重，
   需扩展为按 `sourceId` 去重，或由调用方保证）。
- 前端 `completeCandidate` 的“撤回”逻辑对 Routine 已不还原序列（正确），无需改动。

**回归点**：见 §7 的 B5 项。

## 3. 功能增强设计

### F1　事项计时器：开始/暂停 + 实际耗时入统计（P0）

**现状**：`CandidateCard` 的“开始”按钮仅 `pushToast("已开始…")`，无任何计时；归档耗时
`durationMinutes` 目前只写 `suggestedDurationMinutes`（预计时长）。

**目标**：
- 点“开始”→ 该事项进入“进行中”态，卡片右侧显示**已用时长**（`mm:ss` 或 `hh:mm:ss` 实时走动）；
- “开始”按钮变为“暂停 / 继续”；
- 点“完成”→ 归档条目 `durationMinutes` 写入**实际耗时**（累计时间，四舍五入到分钟，至少 1 分钟）；
- 统计页的耗时统计（`stats.rs` 已按归档 `durationMinutes` 聚合）自动反映真实耗时。

**实现方案**：
- **计时态放前端 Zustand + `localStorage` 持久化**（webview localStorage 跨重启保留，满足“重启恢复”）：
  - `timers: Record<sourceId, { sourceType, title, startedAt, accumulatedMs, running }>`；
  - 全局**同一时刻仅一个 running**（开始新事项时自动暂停上一个，符合“此刻做一件事”心智）；
  - 每秒 `tick` 更新当前 running 项的累计值。
- `CandidateCard` 右侧渲染计时：`running` 显示实时时长 + “暂停”；`paused` 显示累计 + “继续”；
  非计时态显示“开始”。
- 扩展 `CompleteCandidateInput`（`commands.rs` + `api/ipc.ts` + `types/index.ts`）增加
  `duration_minutes_override: Option<i64>`：前端“完成”时传入实际耗时，后端写入 `ArchiveEntry.duration_minutes`；
  未传则回退 `suggestedDurationMinutes`。
- `complete_candidate` 成功后，前端清除该 `sourceId` 的计时态。
- 决策：**单计时器**（而非多事项并行计时）；多并行作为后续可选项记录在案。

**涉及文件**：`useAppStore.ts`（timer 状态/动作）、`CandidateCard.tsx`、`NowPage.tsx`（如需顶部挂计时）、
`types/index.ts`、`api/ipc.ts`、`commands.rs::complete_candidate`。

### F2　跳过二次确认 + 稍后延时 + 撤回（P1）

**现状**：`CandidateCard` 的“跳过/稍后”仅调用 `hideCandidate(sourceId)`（加入会话内
`hiddenCandidates` Set）并弹一条不可撤回的 Toast；“稍后”无延时语义。

**目标**：
- **跳过**：弹**二次确认**（复用 `ConfirmDialog`），确认后当日隐藏；Toast 含“撤回”；
- **稍后**：弹出延时选择（预设 10 / 30 / 60 分钟、1 小时、自定义），到时后**重新出现**并提示；可撤回；
- 两种操作都提供撤回，撤回即从隐藏/稍后集合移除。

**实现方案**：
- 状态扩展（Zustand + `localStorage` 持久化，键带日期，跨日自动失效）：
  - `skipped: Set<sourceId>`（当日跳过）；
  - `snoozed: Record<sourceId, untilIso>`（稍后至某时刻）。
- `hiddenCandidates` 语义升级：由 `skipped ∪ snoozed(未到期)` 计算，替代当前纯会话 Set。
- 新增轻量组件 `SnoozePicker`（预设 + 自定义分钟）与 `CandidateCard` 内“稍后”接入。
- 前端加一个低频定时器（如每 15–30 秒）检查 `snoozed` 是否到期：到期 → 移除 → `refresh()` → Toast
  “「××」稍后时间到，已重新提醒”。
- “跳过”确认：`askConfirm("跳过该事项", "跳过后将当日不再提示，确定？", onSkip)`；`onSkip` 写 `skipped` +
  Toast 含“撤回”（撤回移除 `skipped`）。
- 决策：跳过/稍后**按“天”持久化**（当日有效，跨天自动清理），暂不做跨日持久化。

**涉及文件**：`useAppStore.ts`、`CandidateCard.tsx`、新增 `SnoozePicker.tsx`、`ConfirmDialog.tsx`（复用）。

### F3　日历显示内容与标签筛选（P1）

**现状**：`CalendarPage` 直接渲染 `calendar.occurrences` + `calendar.routineWindows`，无筛选。

**目标**：日历页顶部提供筛选条：
- 显示开关：`事件` / `日常`（可勾选，默认都显示）；
- 标签多选筛选（复用 `TagFilterBar`），仅显示包含所选标签的事件/日常；
- 月/周/日视图统一生效；筛选状态本地持久化（localStorage）。

**实现方案**：
- 前端 `CalendarPage` 增加 `filter` 状态：`{ showEvents, showRoutines, tags: string[] }`；
- 对 `byDate` 的构建做客户端过滤：
  - 事件：`occ.event.tags` 命中标签集；
  - 日常：需由 `routineWindows` 反查 `data.routines` 的 `tags`（`CalendarRoutineWindow` 目前无 tags 字段；
    可在 `get_calendar` 后端补一个 `tags: Vec<String>`，或前端用 `routineId` join `data.routines`，建议后端补字段更稳）。
- 复用 `TagFilterBar` 组件；筛选条与视图切换、前后翻月互不影响。

**涉及文件**：`CalendarPage.tsx`、`types/index.ts`（`CalendarRoutineWindow.tags`）、`commands.rs::get_calendar`（可选）。

### F4　标签输入提示与选择（P1）

**现状**：`Drawer.tsx::TagsField` 是纯文本逗号输入；`ExtensionsPage::TemplateEditor` 同。已有
`listTags()` 返回全部标签，但仅用于过滤条与设置页管理。

**目标**：设置标签时，输入框下方/聚焦时展示**已有标签候选**（点击即加入），同时允许输入**新标签**
（Enter/逗号确认）。

**实现方案**：
- 新增 `TagInput` 组件：芯片列表（可删除）+ 文本输入框；
  - 聚焦或输入时，从 `useAppStore.tags` 过滤出匹配的已有标签作为下拉候选；
  - 点击候选 → 加入；输入新词 + Enter/逗号 → 加入；
  - 失焦自动保存（沿用 `saveDraft`）。
- 替换 `Drawer.tsx::TagsField` 与 `TemplateEditor` 的标签输入；`SettingsPage` 标签管理保持不变。

**涉及文件**：新增 `src/components/TagInput.tsx`；`Drawer.tsx`、`ExtensionsPage.tsx`。

### F5　系统级提醒 + 优先级分级（P0）

**现状（已定位）**：
- `src-tauri/src/lib.rs::check_and_notify` 仅在 `setup`（启动）与 `RunEvent::Resumed`（睡眠唤醒）时触发，
  **无后台定时调度**，因此软件常驻/最小化期间不会弹系统通知；
- `candidates.rs::build_reminders` 的 `should_notify` 只由「全局开关 + 免打扰」决定，**不看优先级**；
- 前端「现在」页会显示 `dueReminders`（应用内横幅），但系统级通知缺失。

**目标**：
- 常驻托盘/最小化状态下，到点也能弹**系统级通知**；
- **分级提醒**：高优先级事件在开始前系统级提醒；中/低优先级仅「现在」页应用内显示（**具体分级可配置**）；
- 免打扰与全局开关仍生效。

**实现方案**：
1. **后台调度**：在 `lib.rs` 增加一个周期线程（如每 30 秒）调用 `check_and_notify`；
   复用 `state.notified`（`kind:sourceId:localDate`）去重，避免重复弹窗；
   线程受 `Arc<AtomicBool>` 停机标志控制（退出/重启安全）。
2. **配置新增 `notifications.priorityPolicy`**：
   ```jsonc
   "notifications": {
     "priorityPolicy": { "high": "system", "normal": "app", "low": "app" }
     // 取值：system=系统级通知；app=仅应用内；off=不提醒
   }
   ```
   默认 `high=system, normal=app, low=app`（契合“高系统级、中低仅应用内”，并保持“低打扰”原则）。
3. **提醒引擎**：`ReminderNotice` 增加 `priority: Priority` 字段；`build_reminders` 按来源事项优先级
   计算 `should_notify = 全局开关 && !免打扰 && policy(priority) == "system"`。
   事件开始/提前提醒携带事件优先级；日常窗口提醒携带日常优先级；浮动截止携带浮动优先级。
4. **前端**：`NowPage` 的应用内横幅对 `should_notify=false` 的项标注“仅应用内”（已有雏形），
   并按新 `priorityPolicy` 文案区分；`SettingsPage` 增加“分级提醒”三档选择。
5. **后台调度与移动端服务共存**：调度线程只读 `Storage` 重算候选，与现有被动刷新逻辑共用
   `check_and_notify`，不引入新的存储写。

**涉及文件**：`lib.rs`（调度线程）、`candidates.rs`（`ReminderNotice` + `build_reminders`）、
`models.rs`（`PriorityPolicy` + `Config` 默认）、`storage.rs`（迁移）、`types/index.ts`、
`NowPage.tsx`、`SettingsPage.tsx`。

> 说明：V1 文档曾将“后台常驻精准推送”作为 V1.5 高级特性，本次按反馈正式纳入 V3.0。

### F6　打开当前数据目录（P2）

**目标**：设置页“数据目录”旁增加“打开”按钮，直接用系统文件管理器打开当前数据目录。

**实现方案**：
- 新增后端命令 `open_data_dir()`：读取当前 `Storage::data_dir()`，Windows 下调用
  `explorer.exe <path>`（`std::process::Command`）；跨平台预留（macOS `open`、Linux `xdg-open`）。
- `SettingsPage` 在“数据目录”Row 增加“打开”按钮；`auto` 时也能打开默认目录。

**涉及文件**：`commands.rs`、`lib.rs`（注册命令）、`api/ipc.ts`、`SettingsPage.tsx`。

## 4. 数据与配置变更（v2 → v3 迁移）

**结论**：事件 / 日常 / 浮动事项 / 归档结构**零改动**，仅 `Config` 新增 `notifications.priorityPolicy` 段；
计时器、跳过/稍后均走前端 `localStorage`，不落数据文件，无需迁移。

**迁移函数（`src-tauri/core/src/storage.rs`）**：
- `CURRENT_VERSION: 2 → 3`；
- 新增 `migrate_v2_to_v3`：对**配置类文件**（含 `notifications` 键）补齐：
  ```jsonc
  "notifications": {
    // 保留既有 enabled/sound/doNotDisturb
    "priorityPolicy": { "high": "system", "normal": "app", "low": "app" }
  }
  ```
- 事件/日常/浮动/归档/templates 文件不写入该段（避免污染数据文件）。

**默认值（`models.rs::Config::default`）**：同步增加 `PriorityPolicy` 默认值，保证新装用户一致。

**兼容保证**：沿用既有规范——serde 忽略未知字段（前向兼容）；`version` 高于当前版本拒绝加载
（`NewerVersion`）；原子写入、`.bak`、mtime 检测、软删除、时区策略全部不变。

## 8. 风险与决策点

| 项 | 内容 | 决策 |
| --- | --- | --- |
| 计时器并发 | 多事项并行计时 vs 单计时器 | 首版**单计时器**，开始新事项自动暂停上一个 |
| 计时器持久化 | 落数据文件 vs localStorage | 用 **localStorage**（跨重启恢复、无需迁移） |
| 跳过/稍后持久化 | 会话级 vs 当日级 | **当日级**（localStorage 带日期，跨天清理） |
| 后台调度功耗 | 周期轮询的常驻开销 | 30 秒低频率轮询 + 事件时间预计算地平线，开销极小 |
| 系统通知平台差异 | Windows 通知 API 差异 | 仅面向 Windows，沿用标准通知 API 并保留应用内横幅降级 |
| 移动端白屏 | 需真实网络复现 | 交付前在真实手机 + LAN IP + 防火墙开/关两种场景验证 |
| 分级提醒默认值 | 旧用户升级后行为 | 默认 `high=system, normal=app, low=app`，保持“低打扰”，迁移补默认值 |
