## 4. 产品与架构约束

### 4.1 编辑授权和离线行为

- 未启用同步：保持本地独立编辑。
- 已启用同步：启动进入检查状态，完成恢复检查、版本确认及锁获取后才进入可编辑状态。
- 有效租约期间允许暂时断网编辑；到期或检测到令牌失效后转只读，保留所有待上传数据。
- 无法确认编辑权时允许查看缓存、导出与重试；禁止创建/修改/删除、完成/撤回、批量操作及计时会话落库。
- 计时器在本设备授权有效时启动；失去编辑权后保存计时草稿并暂停，不静默丢弃或重复写会话。
- 冲突时同时保留本地恢复副本和远端版本，由用户明确选择；默认不自动覆盖任何一方。

### 4.2 同步协议不变量

1. 业务写入与 dirty/本地变更代数持久化关联，启动及退出补做指纹核对。
2. 上传基于明确的 baseRevision；远端版本变化则冲突，不自动推进基准版本。
3. 获取/续租/接管有可校验令牌；过期接管经用户明确操作，接管后先重新确认远端版本。
4. 上传不可变快照后，只有持有效授权且基准版本未变化的设备可发布 manifest。
5. 旧请求不能覆盖新请求的状态；传输期间新增本地修改仍保持待上传状态。
6. 下载前全量校验，提交失败完整回滚；崩溃重启能恢复中间状态。
7. 同步凭据、运行计时器、设备配置和恢复副本不进入远端业务快照。
8. 删除记录及历史归档同步后不能被残留文件复活。

### 4.3 竞争一致性的技术门槛

M1 必须以自动化竞争测试和真实测试空间验证七牛当前接入方式是否提供适用的条件写入/版本比较机制。不能把“写完后读回令牌”当作完整并发保证。

若具备可靠条件写入，则实现锁与 manifest 的条件提交；若不具备，则采用最小协调服务保存租约及提交版本，对象存储继续保存加密快照。需新增云资源时先完成本地可演示实现，再提交具体部署方案、费用和权限需求。该决策是发布前置条件，不能在无互斥保证时宣称安全同步。

### 4.4 凭据和配置

当前个人使用版本可保留用户自备、权限受限的 AK/SK 接入，使用系统凭据库，禁止硬编码和日志泄露，并修正文档中的不实承诺；不把主账号长期密钥作为推荐配置。若协调服务落地，优先由其签发受限短期凭证。

明确同步白名单：业务实体、模板、归档、标签颜色和候选规则。时区、主题、通知偏好逐项确定是否跨设备；设备名称、数据目录、自启动、快捷键、权限和运行计时器保持设备独立。快照应用后同步刷新后端配置缓存与前端 store。

## 6. 必须执行的同步验收矩阵

| 场景 | 预期与核验内容 | 验证层 |
| --- | --- | --- |
| 未配置同步 | 本地功能正常，无网络依赖 | 自动 + GUI |
| 空设备首次下载 | 明确识别空业务数据，下载后完整一致 | 自动 + 双端 |
| 本地与远端都有数据 | 明确选择，取消不改任何一方 | 自动 + GUI |
| 两设备同时获取锁/发布 | 仅一方拥有有效编辑授权，另一方只读；manifest 无双成功 | 竞争测试 + 真实云端 |
| 锁被接管/租约到期 | 原设备停止写入并保留草稿，禁止旧令牌上传 | 自动 + 双端 |
| 本地有改动而远端已前进 | 进入冲突，本地副本保留，远端不被覆盖 | 自动 + 双端 |
| 最后编辑后立即退出/杀进程 | 修改不丢，退出成功上传或重启恢复待上传 | 故障注入 + 双端 |
| 上传快照后 manifest 失败 | 旧生效版本可读，重试安全，无错误清 dirty | 自动 |
| 网络请求延迟期间再次编辑 | 新修改仍待上传，旧上传不能清掉新 dirty | 自动 |
| 下载成功后首次 tick | 不把刚下载的数据误判为本地新修改 | 自动 |
| JSON/密文损坏、错误口令 | 不 panic、不写一半、不清空状态，原数据完整 | 自动 |
| 路径穿越/绝对路径/超大包 | 拒绝在数据目录外写入，内存与解压受限 | 自动 |
| 应用中途磁盘失败/进程中断 | 完整回滚或进入可恢复状态，错误如实显示 | 故障注入 |
| Android 后台回收后重启 | 检测草稿、版本及锁，计时不重复、数据不丢 | 真机 |
| 删除及撤回往返同步 | 无幽灵事项，归档与长期会话统计一致 | 自动 + 双端 |
| 凭据更新/断开/切换空间 | 未上传数据可保留，状态不串空间，设备配置不泄漏 | 自动 + GUI |

## 7. 质量门槛与性能预算

常规验证入口（命令在各自目录运行）：

```powershell
# 项目根目录
. ./.tools/build-env.ps1
./.tools/verify.ps1
# src-tauri 目录
cargo test -p schedule-core --offline
cargo test -p schedule-app --lib --offline
cargo check -p schedule-app --offline
```

新增同步接口测试和前端授权测试应接入统一验证脚本；不以机械增加测试数量作为目标。Android 编译、Windows 打包与真机验收独立记录。

建议性能预算，M0 记录设备基线后确认：

- 无网络等待的本地写入在标准测试数据下 p95 ≤ 300ms。
- 网络故障时导航、只读查看和取消入口保持可操作；配置超时后在约定期限内结束等待。
- 正常网络下最后编辑停止后约 30 秒进入自动上传，连续编辑不产生无限并发请求。
- 对 10,000 条事项、24 个月归档记录同步耗时、峰值内存及流量，针对超预算项优化。
- Release 包剥离调试符号，记录实际体积与 Debug 对比；不在缺乏构建证据时承诺固定 MB 数。
