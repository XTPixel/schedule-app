# 此刻 MOMENT 2.0.0-rc.1：验收与发布说明

历史记录，更新日期：2026-10-24。本文件保留RC1当时的产物、实测结果及未完成门槛；当前版本及发布决定见[2.0.0发布说明](V2.0_Lite_2.0.0_发布说明.md)。下文的待验收状态不代表当前状态，也不能把RC1测试当作最终二进制实测。更早结果保留在beta.2记录中。

## 版本、产物与安装

- 应用版本 `2.0.0-rc.1`，数据格式仍为 v6；同步使用不可变协调记录协议 v2。
- Android：最低 Android 8 / API26，target API36，正式交付 ARM64 Release APK。系统浏览组件还须具备现代 JavaScript 功能；Android 8 的 Chrome69 已验证可以显示更新指引，尚未在该系统上验证更新后浏览组件的完整功能。浏览组件被禁用时先显示原生引导，不会直接创建 WebView。
- Android versionCode 为 `200000050`，高于 beta.2 的 `200000002`。MSI ProductVersion 为 `2.0.50`，高于 beta.2 的 `2.0.2`；正式 2.0.0 预留为 `2.0.99`。
- 产物目录：`.build-cache/releases/2.0.0-rc.1/`。逐文件大小、SHA-256、签名及源码清单分别见 `manifest.json`、`sources.json`、`SHA256SUMS.txt` 和包旁的校验记录；不能用文件名判断签名或验收状态。
- Android 正式安装使用 `MOMENT-2.0.0-rc.1-arm64-release.apk`；`release-test-signed.apk` 使用 Debug 测试证书。Debug、未签名包及 `com.personal.schedule.qa` 测试包不作为正式安装包分发。
- 项目签名证书 SHA-256：`aef96e480b4ec12fe56b716167a2d154139561f03579fa7c96f7fb0fca12028d`。已验证用户生成的加密可携带备份；离线副本的保存情况未验证。维护者需妥善保存该备份与自己设置的密码，后续升级沿用同一证书。
- Windows MSI/EXE 当前没有 Authenticode 签名，安装时可能显示未知发布者。MSI 中的程序与独立 EXE 仅有 Tauri 预期的三字节安装类型标记差异，两个文件分别记录哈希。

手机现有的 `com.personal.schedule` 使用 Debug 测试证书。正式证书包无法直接覆盖它；迁移前须从设置导出加密备份并验证可恢复，再由设备所有者决定卸载及安装时机。本轮没有卸载原手机应用，覆盖测试后保留 RC1 Debug，原有七个业务 JSON 的指纹均与云端测试前基线一致。

## RC1 关闭的问题

1. 空返回 IPC 的 JSON `null` 曾与“用户取消”混淆，成功删除后界面没有刷新或撤回。写入类空结果已在前端 API 层归一化。
2. 活跃计时增加十秒检查点，并在隐藏、失焦恢复和页面退出边界保存。进程重启后恢复为暂停，关闭期间不累加；异常终止会恢复此前成功持久化的检查点。Android强制停止两次观察到约0.84秒和0.71秒的读数回退，因此不保证恢复结束前最后一次显示的毫秒数。跨夜暂停、有效耗时与强制结束进程后的恢复均有真实 UI/原生证据。
3. 被动读取曾重建外部文件修改基线，使旧草稿写入时失去冲突保护。现在仅初次读取、明确重载或本应用成功写入认可基线；外部创建、删除及刷新后的覆盖都有核心回归。
4. 损坏文件备份改用排他创建及递增后缀，同一时间戳和并发备份不会互相覆盖。普通 JSON 临时文件写入后同步到磁盘，再原子替换。
5. 普通业务文件、配置或事务损坏均进入恢复界面。可选择本地恢复点或导入经验证的加密/普通备份；取消、错误口令和无效文件保持原数据，成功恢复前保留原始损坏内容。
6. Android 系统提醒持久化到原生通知仓库，支持重新启动后的恢复、静音通道、精确定时状态及重新规划。真机优化包暴露了 Jackson 反射属性被 R8 移除的问题，现已保留通知结果与调度模型的反射成员。
7. Android 7 实测在框架初始化时缺少 `BootstrapMethodError`，最低安装版本修正为 API26。旧浏览组件有经典脚本提示；完全缺少浏览组件时使用原生启动引导。

## 安装器 CI

`.tools/windows-installer-matrix.ps1` 默认只在 D 盘准备测试 MSI，并独立读取 MSI 表和二进制流验证夹具。真实候选 MSI 保持原字节；测试夹具复用候选程序，改变 MSI 版本与产品编号，不能据此声称验证了历史应用数据迁移。

实际矩阵包括全新安装、较低版本升级、降级拒绝、延迟自定义动作失败后的回滚、卸载和重新安装。`-Execute` 必须同时满足临时 Windows GitHub runner、项目位于 D 盘、显式执行开关；本机拒绝执行的保护已验证。Verify 工作流手动运行或推送到 `codex/release-2-0-rc1` 时执行安装矩阵，并保留脱敏结果和日志。用户已授权将成果提交到该分支并运行Actions；运行结果另行记录，不能把授权或夹具准备视为安装通过。

CI产物同时保留MSI、独立EXE和验收证据。`.tools/import-ci-package.ps1`仅接受成功运行、匹配的应用输入、GitHub产物摘要及全部安装测试通过的文件；交付目录采用该次实际测试的MSI/EXE字节，本机先前构建另存于`.build-cache/github-ci/pre-ci-local/`。接收后应重新生成清单及校验和，不再用本机旧产物覆盖交付文件。

- 等待包含Windows优化程序冷启动/重开恢复的CI运行结束，接收实际测试包并固定最终哈希。
- 在隔离环境实际运行 Windows 安装矩阵。宿主机为 Windows10 家庭中文版，构建19045；用户于2026-10-24明确取消本轮Windows11实测要求，Windows11保留“未验证”的兼容说明，不再作为本轮阻断项。CI Windows Server结果不表述为Windows11桌面实测。

- 补齐验收计划仍未关闭的故障/交互组合；不能用已有正常路径覆盖结果替代未测案例。

这些条件完成前保持 `formalRelease:false`，不把候选包改称稳定正式版。源码、签名私钥、真实数据、测试证据和构建产物按仓库忽略规则分别保管，所有项目编译缓存、临时目录、模拟器及产物均位于 D 盘。
