## 三、版本迁移逻辑（子目标 1）

**版本现状**：MVP 已落盘 `version: 1`；Phase1/2 未新增破坏性结构字段（`repeat`/`reminders`/`durationMinutes`/`tags` 等字段在 MVP 即以 serde 默认值预留），因此**无需升级版本号**，老数据直接加载。

**迁移函数（`src-tauri/core/src/storage.rs`）**：`migrate_v0_to_v1` 已从「骨架示例」补全为完整迁移，处理：
- 写入 `version = 1`；
- 事件补全 `description/end/allDay/reminders/repeat/tags/priority/status/completedAt/deletedAt`；
- 日常补全 `timeWindows/durationMinutes/tags/priority/enabled/deletedAt`；
- 浮动事项补全 `deadline/tags/status/sortOrder/completedAt/deletedAt`；
- 配置补全 `timezone/dataDir/notifications/appearance/behavior/candidate`；
- 归档天补全 `entries/summary`。

**兼容保证**：
- serde 对未知字段一律忽略（前向兼容）；
- 高于当前版本的 `version` 拒绝加载并报错（`NewerVersion`，含「导出/升级」提示）；
- 旧 JSON 的 `events/routines/tasks/archive` 结构不变，字段只增不减。

## 四、关键业务语义说明

1. **重复事件完成语义（§4.4）**：重复事件展开为实例，实例键 `e_xxx#2025-01-15`。点「完成」时后端 `complete_candidate` 仅写入一条 `sourceId = 实例键` 的归档，**不修改序列本身**；后续实例不受影响。终止整系列需在抽屉修改 `repeat.end` 或删除事件。候选引擎用「当日归档集合」过滤已完成的实例。
2. **自然语言兜底（§7.5）**：`parse_nl` 解析失败返回 `matched=false`，前端不报错，改为打开右侧抽屉、标题预填原文、时间高亮引导手动修正（默认当前时间 +1 小时）。
3. **多级提醒（§4.5）**：提醒引擎遍历事件 `reminders` 全部偏移量（5/10/15/30/60/120/1440 分钟等预设），重复事件按实例展开到「最大偏移天数 + 1」的地平线内逐实例判断。
4. **免打扰（§4.5/§8.3）**：免打扰仅抑制系统通知（`should_notify = 全局开关 && !免打扰时段`）；应用内「现在」页始终展示提醒横幅，并标注「免打扰 · 仅应用内」。
5. **时区（§5.8）**：重复事件按墙钟时间展开（每次发生保持与首发生相同的本地 HH:mm）；全天事件按纯日期；绝对时刻仍落盘 UTC `Z`。
6. **自定义数据目录**：默认目录下写指针文件 `data_dir.txt`（一行绝对路径）。启动时优先读指针解析数据目录；`set_data_dir` 迁移现有数据（目标为空才复制）并切换内存 Storage；`"auto"` 恢复默认并删除指针。
7. **导入导出**：导出到 `{目标目录}/schedule-export/`（config/events/routines/tasks + archive/ 全部月份）；导入先经 `Storage::load_all` 校验（含迁移/版本拒绝），再写回当前数据目录；导入的配置**保留当前 `dataDir`**，避免切换目录后互相覆盖。

## 五、编译与运行

```powershell
# 前端（已验证通过：tsc 0 错误 + vite build 成功）
npm run build

# 后端（已验证通过：cargo check 0 错误 0 警告；cargo test -p schedule-core 8 用例全绿）
cd src-tauri
cargo build --release

# 运行
npm run tauri dev      # 开发
npm run tauri build    # 打包
```

> 注：`src-tauri` 新增 `tauri-plugin-global-shortcut`、`tauri-plugin-dialog` 两个官方插件依赖，首次构建需联网拉取 crates.io 依赖。
