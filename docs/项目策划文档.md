> 版本：v0.6（草案，已通过三轮评审）
> 日期：2025-01
> 状态：待评审

---

## 1. 项目概述

### 1.1 一句话定位

一款**本地运行、数据自持、常驻托盘**的个人日程管理软件，通过「事件」「日常」「浮动事项」三类数据，结合当前时间，告诉你**此刻该做什么、可以做什么**，并把每天真正做过的事归档下来，形成可复盘的个人时间账本。

### 1.2 背景与动机

现代人的时间管理有两个高频痛点，且往往被现有工具割裂处理：

1. **想做什么怕忘记** —— 有一件具体的事，某个时间点必须做（开会、缴费、吃药、还书、交材料）。这类是**有时限、一次性**的任务，需要提醒。
2. **某时不知道该做什么** —— 有大量「应该做但没排具体时间」的事（读书、锻炼、学习、家务、习惯打卡）。在某个空闲时刻，面对这些事反而无所适从，最终刷手机度日。

现有工具的问题：日历应用只管理「有时限事件」，待办清单只管理「无时限任务」，两者数据不互通，也**没有一个「现在」的整合视图**。用户真正需要的，是在任意时刻打开软件，第一眼就看到「现在该做什么」。

本软件将三类数据统一，以「当前时间」为第一视角进行聚合推荐，并用本地 JSON 文件保证数据完全自主可控。

### 1.3 目标

- **记住**：不遗漏有时限的事件。
- **指引**：在任意时刻告诉用户「现在该做什么 / 可以做什么」。
- **沉淀**：把每天实际做的事归档，形成可查询、可复盘的历史。
- **轻量**：本地运行、常驻托盘、低打扰、低资源占用。

### 1.4 核心原则（设计红线）

| 原则 | 说明 |
| --- | --- |
| 本地优先 | 数据只存在本机 JSON 文件，无云端依赖，无账号体系 |
| 数据可读 | JSON 明文、结构清晰，用户可自行查看、备份、用 Git 或脚本处理 |
| 时间第一视角 | 所有界面默认围绕「现在」展开，而非围绕「列表」展开 |
| 低打扰 | 提示可开关、可分级，默认不滥用系统通知 |
| 常驻但不侵入 | 最小化到托盘，后台仅做计时与提醒，占用极小 |

## 2. 目标用户与痛点

### 2.1 用户画像

- **主要用户**：有自我管理意愿，但容易忘记或拖延的个人用户（学生、自由职业者、轻度管理者、习惯养成者）。
- **使用场景**：办公室电脑 / 个人笔记本常驻运行；每天多次「看一眼现在该做什么」；晚上或周末复盘。

### 2.2 痛点 → 解法映射

| 痛点 | 具体表现 | 本软件的解法 |
| --- | --- | --- |
| 怕忘记（事件） | 有事但到点忘了、快到了才想起 | 事件 + 多级提前提醒 + 托盘通知 |
| 不知道做什么（日常） | 空闲时刻无所适从 | 时间窗口匹配 + 候选推荐，给出「此刻最优解」 |
| 事件管理繁琐 | 增删改查不顺手 | 一键快录、拖拽调整、批量操作、快捷键 |
| 做了但没记录 | 一天下来不知道时间去哪了 | 一键归档、支持记录计划外事项、日复盘 |
| 工具碎片化 | 日历、待办、习惯分开管理 | 事件/日常/浮动事项/归档四类数据统一存储、统一视图 |
| 数据不受控 | 数据在云上、导出困难 | 本地 JSON、可备份、可版本管理 |

## 3. 核心概念模型

系统围绕五个核心对象设计：

```
事件 Event ──────┐
日常 Routine ────┼──► 候选推荐 Candidate ◄── 当前时间 + 规则
浮动事项 Task ────┘
                    │
                    ▼
              归档 Archive（每天实际做了什么）
```

### 3.1 事件（Event）

- **定义**：有时限的一次性或周期性事项。
- **特征**：有明确的开始时间（可含结束时间、全天），可设提前提醒，可重复。
- **示例**：周三 15:00 开会、每月 1 日交房租、每天 20:00 吃药、3 天后还书。

### 3.2 日常（Routine）

- **定义**：无固定具体时间、但希望在某类时间段内完成的习惯性或常规事项。
- **特征**：定义「时间窗口」（如工作日 08:00–09:00）+ 预计时长 + 重复规则（每周几）。
- **示例**：晨间阅读 30 分钟（工作日 07:30–09:00）、晚间锻炼（每天 18:00–22:00）、周末大扫除（周六全天）。

### 3.3 候选（Candidate）

- **定义**：由系统根据「当前时间」实时计算的推荐结果，回答「现在该做什么」。
- **来源**：进行中/即将开始的事件、当前时间窗口内的日常、逾期未完成的日常、高优先级浮动事项。
- **性质**：候选是**动态计算**的，不持久化；用户从中选择一个「开始做」，或直接归档。

### 3.4 浮动事项（Task）

- **定义**：无固定时间、无时间窗口，但需要完成且有一定优先级的事项。
- **特征**：只有「标题 + 备注 + 优先级 + 标签 + 可选截止日期」，不排入日历，出现在「有空可做」的候选推荐中。
- **示例**：整理简历、给手机换电池、回复一封重要但不紧急的邮件。

### 3.5 归档（Archive）

- **定义**：以「天」为单位，记录当天**实际完成**的事项流水。
- **来源**：① 从候选/事件/日常中勾选「完成」自动写入；② 手动添加计划外事项。
- **示例**：某天归档：「09:15 晨间阅读（日常）」「14:00 项目周会（事件）」「16:40 临时帮同事修电脑（手动）」。

## 4. 功能需求

### 4.1 事件管理

- **创建**：快速录入（输入一句话自动识别时间，如「明天下午3点开会」）；详细表单。
- **字段**：标题、备注、开始/结束时间、全天、重复规则、提前提醒（可多级：如提前 10 分钟 / 1 小时 / 1 天）、标签、优先级。
- **编辑**：拖拽改时间、下拉改提醒、批量选择、复制、快速标记完成/取消。
- **视图**：列表（按时间）、日历（月/周/日）、时间轴。
- **检索**：按标题、标签、日期范围搜索。

### 4.2 日常管理

- **创建**：定义标题、时间窗口（支持多个窗口 + 每周重复）、预计时长、标签、优先级、启用开关。
- **编辑**：与事件一致的便捷编辑体验；可暂停（停用）而不删除。
- **展示**：在「今天」视图中以时间轴形式铺开，标注当前处于哪个窗口。

### 4.3 浮动事项管理

- **创建**：轻量录入（只需标题），可设优先级、标签、备注、可选截止日期。
- **编辑**：拖拽排序（`sortOrder` 即顺序）、标记完成/归档、一键转成事件（补上时间）或转成日常（补上窗口）。
- **展示**：独立列表视图；在「现在」页作为「有空可做」的候选来源。

### 4.4 「现在该做什么」候选推荐（核心）

- **首屏即答案**：打开主界面，顶部醒目展示当前时间 + 当前最优候选（1 个主推荐 + 若干次选）。
- **候选排序规则**（详见第 8 章）：事件紧急度 > 事件临近度 > 日常窗口匹配度 > 逾期日常 > 浮动高优先级。
- **一键操作**：对候选可「开始 / 完成 / 跳过 / 稍后提醒」。
- **重复事件完成语义**：对重复事件点「完成」默认只归档**本次发生**（本次不再提醒），后续重复实例不受影响；终止整个系列需进入编辑界面修改 `repeat.end` 或删除事件。
- **刷新机制**：随系统时间自动刷新；托盘菜单也可直接看当前候选（不打开主窗口）。

### 4.5 提示与通知

- **提醒类型**：事件的提前提醒、事件开始提醒、日常窗口开始/即将结束提醒、浮动事项截止日提醒。
- **通知方式**：系统通知（托盘气泡）、应用内角标、可选声音。
- **开关粒度**：全局开关（托盘快捷切换）、按事件/日常单独开关。
- **免打扰**：可设置免打扰时段（如 22:00–08:00 不弹系统通知）。

### 4.6 归档与复盘

- **一键归档**：从候选列表勾选「完成」即写入当日归档；也可手动添加任意事项（含标题、时间、备注、关联来源、可选耗时）。
- **日视图**：某天按时间轴列出所有完成事项，可补记、修改、删除。
- **复盘辅助**：统计每日完成数、各标签耗时占比、日常完成率（后移至 V1.5）。

### 4.7 托盘与常驻

- **最小化到托盘**：关闭主窗口默认缩到托盘而非退出，托盘菜单可真正退出。
- **托盘菜单**：当前候选速览、快捷新增、通知开关、打开主界面、退出。
- **开机自启**（可选）、全局快捷键唤起（可选，如 `Ctrl+Shift+A` 打开「现在该做什么」）。

### 4.8 其他

- **数据备份**：一键导出/导入全部 JSON；数据目录默认位于用户数据目录，支持自定义；可放入网盘/Git 自行同步，但**不支持多端同时读写同一目录**（后保存会覆盖先保存）。
- **标签与统计**：标签管理、按标签过滤；基础统计图表。
- **主题**：浅色 / 深色 / 跟随系统。

## 5. 数据设计（JSON）

### 5.1 目录结构

```
data/
├── config.json            # 应用配置（通知、主题、免打扰、数据目录等）
├── events.json            # 全部事件
├── routines.json          # 全部日常
├── tasks.json             # 全部浮动事项
└── archive/
    ├── 2025-01.json       # 按月归档（每天一个条目）
    ├── 2025-02.json
    └── ...
```

> 归档按月分文件，避免单文件无限增长；事件与日常量级小（数百～数千条），单文件即可。

### 5.2 `events.json`

```json
{
  "version": 1,
  "events": [
    {
      "id": "e_9f2c1a",
      "title": "项目周会",
      "description": "同步本周进度",
      "start": "2025-01-15T14:00:00+08:00",
      "end": "2025-01-15T15:00:00+08:00",
      "allDay": false,
      "reminders": [
        { "offsetMinutes": 10 },
        { "offsetMinutes": 60 }
      ],
      "repeat": null,
      "tags": ["工作", "会议"],
      "priority": "high",
      "status": "active",
      "createdAt": "2025-01-10T09:00:00+08:00",
      "updatedAt": "2025-01-12T11:30:00+08:00",
      "completedAt": null,
      "deletedAt": null
    }
  ]
}
```

> 存储归一化：`start`/`end`/`createdAt` 等绝对时刻字段，API 入站接受任意 ISO 时区，落盘统一转为 UTC `Z`（示例以 `+08:00` 呈现，两者等价）；详见 §5.8。

`repeat` 结构（可选）：

```json
{
  "type": "daily | weekly | monthly | yearly | custom",
  "interval": 1,
  "daysOfWeek": [1, 3, 5],
  "end": "2025-12-31T00:00:00+08:00 | null"
}
```

### 5.3 `routines.json`

```json
{
  "version": 1,
  "routines": [
    {
      "id": "r_3ab7d2",
      "title": "晨间阅读",
      "description": "读 30 分钟",
      "timeWindows": [
        {
          "daysOfWeek": [1, 2, 3, 4, 5],
          "start": "07:30",
          "end": "09:00"
        }
      ],
      "durationMinutes": 30,
      "tags": ["学习", "阅读"],
      "priority": "normal",
      "enabled": true,
      "createdAt": "2025-01-01T08:00:00+08:00",
      "updatedAt": "2025-01-01T08:00:00+08:00"
    }
  ]
}
```

### 5.4 `tasks.json`

```json
{
  "version": 1,
  "tasks": [
    {
      "id": "t_5c8e2f",
      "title": "整理简历",
      "description": "更新到最新版本并导出 PDF",
      "priority": "high",
      "deadline": "2025-02-01T00:00:00+08:00",
      "tags": ["求职", "个人"],
      "status": "active",
      "sortOrder": 1,
      "createdAt": "2025-01-10T10:00:00+08:00",
      "updatedAt": "2025-01-12T15:00:00+08:00",
      "completedAt": null
    }
  ]
}
```

> `sortOrder` 用于手动拖拽排序，作为「有空可做」时候选的默认优先级；`deadline` 为可选字段，有则参与临近度加权。

### 5.5 `archive/2025-01.json`

```json
{
  "version": 1,
  "month": "2025-01",
  "days": {
    "2025-01-15": {
      "entries": [
        {
          "id": "a_7d1e9f",
          "time": "09:15",
          "title": "晨间阅读",
          "source": "routine",
          "sourceId": "r_3ab7d2",
          "note": "读了《XXX》20 页",
          "durationMinutes": 30,
          "doneAt": "2025-01-15T09:15:00+08:00"
        },
        {
          "id": "a_8e2f0a",
          "time": "16:40",
          "title": "帮同事修电脑",
          "source": "manual",
          "sourceId": null,
          "note": "临时帮忙，约 40 分钟",
          "durationMinutes": null,
          "doneAt": "2025-01-15T16:40:00+08:00"
        }
      ],
      "summary": "整体不错，下午被临时事项打断",
      "updatedAt": "2025-01-15T22:00:00+08:00"
    }
  }
}
```

> `durationMinutes` 为可选字段（不强填）：来自候选/事件/日常时可用预计时长预填，手动记录可留空，用于 V1.5 的耗时统计。
> `time` 为**显示用时间**（来自来源的预计时间或用户补记时填写）；`doneAt` 为点击「完成」时的**系统时间戳**，用于时序排序。两者可不同（如计划 14:00 开会、实际 14:20 才完成归档）。

### 5.6 `config.json`

```json
{
  "version": 1,
  "timezone": "Asia/Shanghai",
  "notifications": {
    "enabled": true,
    "sound": false,
    "doNotDisturb": { "enabled": true, "start": "22:00", "end": "08:00" }
  },
  "appearance": { "theme": "system" },
  "behavior": {
    "minimizeToTray": true,
    "launchAtStartup": false,
    "globalHotkey": "Ctrl+Shift+A"
  },
  "candidate": { "missedRoutineGraceHours": 4 },
  "dataDir": "auto"
}
```

> `dataDir` 默认 `"auto"`（用户数据目录，如 Windows `%APPDATA%\<AppName>`），也可改为自定义绝对路径。
> `candidate.missedRoutineGraceHours`：逾期日常可补宽限小时数（默认 4），MVP 阶段硬编码、V1.0 开放用户自定义。

### 5.7 数据一致性约定

- 所有写入采用「**先写临时文件 → 原子重命名**」策略，避免写入中断导致 JSON 损坏。
- 文件加载失败时保留 `.bak` 备份并提示用户，不静默覆盖。
- **版本迁移（执行）**：启动时校验 `version`；低于当前版本时显式执行 `migrate_v{n}_to_v{n+1}()` 迁移函数（字段补全/默认值填充），迁移骨架在 MVP 阶段即搭好；高于当前版本时拒绝加载，并在报错界面提供「**导出数据**」按钮（把 JSON 原样保存到用户指定目录），再提示「请安装较新版本以读取此数据」，保证数据不被锁死。
- **字段分阶段启用**：Phase 0 仅消费基础字段；`repeat`/`reminders` 为 Phase 1 预留、`durationMinutes` 为 V1.5 预留。读取时对未知/未启用字段一律忽略，保证 Schema 前向兼容（避免为未实现功能预先承载冗余结构）。
- **外部修改检测（防脑裂）**：启动与每次写回前检测文件 `mtime`；若被外部修改，无本地未保存改动时自动重载，有未保存改动时提示用户选择「放弃本地并重载」或「保留本地并覆盖外部」。
- **软删除**：事件/日常/浮动事项删除时写 `deletedAt` 而非物理删除；归档展示时若 `sourceId` 找不到对应源，降级显示为「已删除的事项（仅保留文本）」。
- 所有对象使用短 ID（`e_`/`r_`/`t_`/`a_` 前缀 + 随机串），保证归档与来源可关联。

### 5.8 时间与时区存储策略

- **绝对时刻**（一次性事件的 `start`/`end`、归档 `doneAt`、浮动事项 `deadline`、各 `createdAt`/`updatedAt`）：**API 入站接受任意 ISO 时区，落盘统一归一化为 UTC `Z`**；显示时按 `config.timezone` 转本地。示例（§5.2 等）中的 `+08:00` 属「入站写法」，与 `Z` 等价，非落盘格式。
- **墙钟时刻**（重复规则、日常 `timeWindows` 的 `start`/`end`）：存 `HH:mm` 本地墙钟，跨时区仍按「当地时间」触发（如每天 20:00 吃药）。
- **纯日期**（全天事件 `allDay`、归档「天」键）：存 `YYYY-MM-DD`，不做时区换算；**全天事件的显示同样跟随存储的纯日期**，不随系统时区漂移（如「周年纪念日」永远显示为存储的那一天）。
- **时区变更**：用户改系统时区或跨国时，绝对时刻不变、仅显示跟随变化；`config.timezone` 变更写入迁移记录，作为数据迁移的第一条基线。

## 6. 技术选型

### 6.1 桌面框架对比

| 方案 | 优势 | 劣势 | 结论 |
| --- | --- | --- | --- |
| **Tauri 2.x** | 体积小（几 MB）、内存占用低（常驻托盘友好）、现代、跨平台 | 需 Rust 工具链，上手门槛略高 | ⭐ 推荐 |
| Electron | 生态最成熟、纯 JS 开发、上手快 | 体积大（100MB+）、内存高，常驻托盘不划算 | 备选 |
| WPF / WinUI | 原生 Windows 体验好、单文件 | 仅 Windows、跨平台无望、开发效率低 | 仅 Windows 限定方案 |

> ✅ 已确认：采用 **Tauri 2.x**，首版仅 Windows。架构上仍保持前端与存储层解耦，便于日后迁移或扩展。

### 6.2 推荐技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 桌面壳 | Tauri 2.x | 托盘、系统通知、自动启动、全局快捷键均由 Tauri 插件提供 |
| 前端框架 | React + TypeScript + Vite | 生态成熟，组件丰富 |
| 样式 | Tailwind CSS + 组件库（shadcn/ui 或 Ant Design） | 现代化、可定制 |
| 状态管理 | Zustand | 轻量，适合本地应用 |
| 本地存储 | Node `fs`（通过 Tauri 命令）读写 JSON | 明文、可备份 |
| 时间处理 | dayjs | 时区/重复规则计算 |
| 打包分发 | Tauri bundler（msi / nsis，Windows） | 一键安装包 |

### 6.3 系统架构

```
┌─────────────────────────────────────────────┐
│                  前端 (React)                │
│ Now视图 │ 日历 │ 事件 │ 日常 │ 浮动 │ 归档 │ 统计 │
└──────────────────┬──────────────────────────┘
                   │ invoke (IPC)
┌──────────────────▼──────────────────────────┐
│              Tauri 后端 (Rust)               │
│  JSON 存储服务 │ 候选推荐引擎 │ 提醒调度器 │ 托盘 │
└──────────────────┬──────────────────────────┘
                   │
            ┌──────▼──────┐
            │  data/*.json │
            └─────────────┘
```

- **候选推荐引擎**与**提醒调度器**放在后端（Rust）。MVP 采用「**被动刷新 + 系统唤醒钩子**」：仅在主窗口打开、或系统从睡眠/休眠恢复（监听 `resume` 事件）时触发全量重算与提醒补发，不依赖后台线程轮询；后台常驻精准推送降级为 V1.5 高级特性。
- 前端只负责展示与交互，通过 IPC 调用后端命令。
- 数据读写集中在「存储服务」模块，保证原子性与一致性。

## 7. 界面与交互设计

### 7.1 设计风格

- **基调**：简洁、留白、卡片化、圆角与柔和阴影，玻璃拟态点缀。
- **配色**：中性色打底 + 单一强调色（用于「现在」与高优先级），深浅双主题。
- **排版**：时间作为第一视觉元素，当前时间与候选大字号突出。
- **动效**：轻量过渡（列表增删、候选切换），不做炫技。

### 7.2 信息架构（页面）

```
┌─────────────┬──────────────────────────────┐
│  导航侧栏    │       主内容区               │
│             │                              │
│  ● 现在     │  [当前时间] [主候选卡片]       │
│    日历     │  [次选候选列表]               │
│    事件     │  [今日时间轴]                 │
│    日常     │                              │
│    浮动     │                              │
│    归档     │                              │
│    统计     │                              │
│  设置       │                              │
└─────────────┴──────────────────────────────┘
```

### 7.3 关键页面

**①「现在」页（默认首页 / 核心）**
- 顶部大号当前时间。
- 主候选卡片：当前最该做的一件事，含「开始 / 完成 / 跳过 / 稍后」。
- 次选列表：其余候选按得分排序。
- 今日时间轴：今天的事件与日常窗口按时间铺开，一眼看清全天。

**② 日历页**：月/周/日切换，事件与日常窗口叠加显示。

**③ 事件页 / 日常页 / 浮动事项页**：列表 + 筛选 + 行内编辑；双击或「更多」展开右侧 480px 抽屉（非模态）编辑高级字段。

**④ 归档页**：日历选择日期 → 当日流水时间轴 → 可补记/编辑/删除。

**⑤ 统计页（V1.5+）**：完成趋势、标签分布、日常完成率。

### 7.4 关键交互流程

- **快速录入**：托盘菜单「快速新增」或全局快捷键 → 弹出迷你输入框 → 输入「明天下午3点开会」→ 自动解析时间 → 回车即存。
- **完成归档**：候选卡片点「完成」→ 写入归档 → 候选列表刷新 → 轻提示「已归档」。
- **记录计划外事项**：归档页「添加记录」→ 填标题 + 时间 → 存为 `source: manual`。

### 7.5 编辑与交互规范（固化）

- **两级编辑**：行内编辑（约 80% 操作）——列表/卡片上单击标题直改文本，时间/日期用下拉滚轮微调，不打开新窗口；详情抽屉（约 20% 操作）——双击或点「更多」从右侧滑出**非模态抽屉**（宽 480px）展示全部高级字段。
- **容器统一**：复杂编辑一律用右侧 480px 抽屉，**禁用模态对话框**遮挡主视图（危险确认除外）。
- **表单分层**：基础区（标题、开始/结束时间）默认展开；高级区（重复规则、多级提醒、标签、优先级）默认折叠。
- **自动保存（V3.1 修订）**：除备注大文本外，**行内编辑**字段失焦即自动保存；**详情抽屉为唯一例外**——抽屉内全部修改仅为本地草稿，底部提供显式「取消 / 保存」按钮，点「保存」才落盘；点 ✕ / 取消有未保存改动时弹「放弃修改？」确认。新建草稿在保存前不产生任何持久化副作用。
- **时间输入**：放弃原生 `datetime-local`，采用自定义下拉滚轮面板，支持键盘直输数字（如输入 `1430` 转成 `14:30`）。
- **拖拽（分场景）**：时间轴/日历上的拖拽仅用于「跨日期移动」，释放后弹迷你确认气泡（含 +15 分钟 / −15 分钟 / +1 小时微调），确认后保存；列表内的拖拽（浮动事项、日常列表）用于调整排序（`sortOrder`），静默保存、不弹气泡。
- **容错与撤销**：完成/删除等操作弹底部 Toast 撤回条（停留 5–7 秒，含「撤回」按钮）；全局 Ctrl+Z 撤销基于内存操作栈（V1.0）。
- **自然语言兜底**：解析失败不报错，自动将输入文本填入标题、默认「当前时间 +1 小时」为开始时间，并高亮时间选择器引导手动修正。

## 8. 候选推荐算法（草案）

### 8.1 输入

当前时间 + 事件列表 + 日常列表 + 浮动事项列表 + 当日归档 + 配置。

### 8.2 打分与排序

候选按类别分层，层内按得分排序：

| 层级 | 类别 | 得分依据 |
| --- | --- | --- |
| 1 | 进行中/即将开始的事件 | 时间临近度 + 优先级；开始时间越近得分越高 |
| 2 | 当前时间窗口内的日常 | 窗口剩余时间占比（越接近窗口结束越紧急）+ 优先级 + 是否今天已完成 |
| 3 | 逾期未完成的日常（窗口结束后 X 小时内） | 逾期时长 + 优先级 |
| 4 | 今天晚些时候的事件预告 | 时间临近度 |
| 5 | 浮动事项（有空可做，无时间） | 优先级 + `sortOrder` + 可选 `deadline` 临近度 |

### 8.3 过滤规则

- 已完成的、已取消的、`enabled: false` 的、已删除（`deletedAt`）的、已归档过的重复项（当天）不参与。
- 日常仅在窗口结束后的 **X 小时**内视为「逾期可补」进入候选；X 由 `candidate.missedRoutineGraceHours` 控制（默认 4，MVP 硬编码、V1.0 开放自定义）。超时自动标记为「今日缺席/跳过」，仅参与复盘统计，不再进入候选推荐。
- 免打扰时段内，仅做「应用内展示」，不弹系统通知。
- 同分时按「最近较少做 / 最久未做」打破平局（提升冷门日常的曝光，避免总推荐同一件事）。

### 8.4 输出

- 主候选 1 个 + 次选 N 个（N 可配置，默认 5）。
- 每个候选附：类型（事件/日常/浮动事项）、来源、建议时长、关联操作按钮。

## 10. 风险与决策记录

### 10.1 技术风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 后台定时与系统休眠冲突 | 唤醒后错过提醒 | MVP 采用被动刷新 + 系统 `resume` 钩子重算补发；后台常驻精准推送后移至 V1.5 |
| JSON 文件损坏 | 数据丢失 | 原子写入 + `.bak` 备份 + 启动校验 |
| Windows 通知/托盘 API 差异 | 提醒体验受系统版本影响 | 仅面向 Windows，用系统标准通知 API 并做好降级 |
| 自然语言解析时间不准 | 快录体验差 | 提供结构化表单兜底；解析失败自动回退 |

### 10.2 决策点（已全部确认）

1. ✅ **桌面框架**：Tauri 2.x（轻量、低内存，契合常驻托盘）。
2. ✅ **目标平台**：首版仅 Windows。
3. ✅ **浮动事项**：作为独立类型，与事件、日常并列。
4. ✅ **归档耗时**：归档记录保留可选 `durationMinutes` 字段（不强填），用于 V1.5 耗时统计。
5. ✅ **统计/复盘**：后移至 V1.5，V1.0 不做。
6. ✅ **数据目录**：默认用户数据目录（可自定义）。
