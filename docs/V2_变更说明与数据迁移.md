## 三、版本迁移逻辑（子目标 1）

**版本现状**：Phase0–2 落盘 `version: 1`。Phase3 新增「模板」独立文件 + 配置新增三个段，
事件/日常/浮动/归档结构**零改动**，因此只需 `1 → 2` 的增量迁移。

**迁移函数（`src-tauri/core/src/storage.rs`）**：

- `migrate_step` 分发：`0 → migrate_v0_to_v1`、`1 → migrate_v1_to_v2`。
- `migrate_v1_to_v2`：
  - 写入 `version = 2`；
  - **仅当文件含 `appearance` 或 `timezone` 键（即配置类文件）**时，补齐：
    - `git`：`{ enabled:false, autoCommit:false, commitIntervalMinutes:60, commitMessageTemplate:"chore(schedule): backup {timestamp}", remoteUrl:null }`
    - `hooks`：`{ enabled:false }`
    - `mobile`：`{ enabled:false, port:8731, password:"" }`
  - 事件/日常/浮动/归档/templates 文件不写入配置段（避免污染数据文件）。

**兼容保证**：

- 旧版（v1）`events/routines/tasks/config/archive` 直接加载，字段只增不减；
- serde 对未知字段一律忽略（前向兼容）；`version` 高于当前版本拒绝加载（`NewerVersion`）；
- 原子写入、`.bak` 备份、mtime 外部修改检测、软删除、时区（UTC Z / HH:mm / YYYY-MM-DD）全部沿用既有规范；
- 新增 `templates.json` 独立文件，版本号直接写 2，不影响旧文件。

## 四、关键业务语义说明

### 4.1 Git 一键备份

- 只封装系统 Git（`std::process::Command`），不内置 Git；未安装时返回友好错误并提示安装地址。
- 一键备份流程：`git init`（如需）→ `git add -A` → `git commit -m <渲染后备注>` → 可选 `git push -u origin HEAD`。
- 提交备注模板支持 `{timestamp}` 占位（替换为 UTC ISO 时间）。
- 「无变更可提交」按成功处理（`nothingToCommit=true`），不视为错误。
- 自动提交后台线程：`git.enabled && git.autoCommit` 时按 `commitIntervalMinutes` 周期提交**本地**快照（**不推送**）；推送仅在手动一键备份时进行。
- 远端地址仅用于手动一键备份；自动提交忽略 `remoteUrl`。

### 4.2 事项模板

- 模板分类：`workday`（工作日）/ `weekend`（周末）/ `custom`（自定义），仅作标记，不强制日期校验。
- 模板条目：`event`（生成事件，支持全天/开始/结束/时长）与 `routine`（生成日常，支持窗口星期/起止时间）。
- **解绑定**：`apply_template` 用 `new_event()/new_routine()` 生成全新对象并写入存储，不写任何 `templateId` 反向引用；修改模板不影响已生成实例。
- **预览确认**：`preview_template_cmd` 返回将要生成的事件/日常（不落盘），前端确认后 `apply_template_cmd` 才写入。
- 模板本身走软删除（`deletedAt`）；前端列表过滤已删除。

### 4.3 脚本钩子

- 数据目录 `hooks/*.js`，每个脚本可声明 `on_event_saved / on_archive_entry_add / on_candidate_refresh`。
- 分发点：事件保存、归档写入、候选刷新（`get_now_candidates`）后；由 `config.hooks.enabled` 开关控制（默认关闭）。
- 入参为只读 JSON 字符串，返回值为「导出输出」，由 `dispatch` 收集；`run_hook_test` 命令可手动触发并查看每个脚本输出。
- **安全边界**：脚本运行在 `boa_engine`（受限 JS 解释器，无文件系统/网络/进程能力）内，**无法修改内部数据文件**；不做复杂沙箱，风险由界面与文档明示。

### 4.4 移动端只读

- `tiny_http` 绑定 `0.0.0.0:<port>`（默认 8731），仅局域网内可访问，不做公网暴露/内网穿透。
- 只读接口：`GET /api/candidates`、`/api/events`、`/api/routines`、`/api/review`；`/` 返回内嵌只读网页。
- **无写接口**：非 GET 一律 405；`/api/*` 全部只读。
- 鉴权：`config.mobile.password` 非空时要求 `Authorization: Bearer <password>`，否则 401。
- 生命周期：`set_config` 检测 mobile 配置变化后 `restart_mobile`；端口占用等启动失败通过 `mobile-start-error` 事件 Toast 提示前端。

## 五、新增配置项说明（config.json）

```jsonc
{
  "version": 2,
  "git": {
    "enabled": false,                       // 是否启用自动备份
    "autoCommit": false,                    // 是否按间隔自动提交本地快照
    "commitIntervalMinutes": 60,            // 自动提交间隔（分钟）
    "commitMessageTemplate": "chore(schedule): backup {timestamp}", // 提交备注模板
    "remoteUrl": null                       // 远端仓库地址（可选，仅手动一键备份时推送）
  },
  "hooks": { "enabled": false },            // 脚本钩子开关（默认关闭）
  "mobile": {
    "enabled": false,                       // 移动端只读开关（默认关闭）
    "port": 8731,                           // 局域网监听端口
    "password": ""                          // 访问密码（空=不鉴权，仍仅局域网）
  }
}
```

## 六、用户侧使用说明片段

### 6.1 Git 备份风险提示

> ⚠️ **网盘同步警告**：若将数据目录放入网盘/Git 同步，**禁止多端同时读写同一个数据目录**，
> 否则后保存会覆盖先保存（脑裂覆盖）。本应用已通过 mtime 检测在写回时提示外部修改，
> 但无法阻止多设备同时写同一目录造成的覆盖。请保证同一时刻只有一个端在运行。

### 6.2 脚本钩子安全警告

> ⚠️ 启用脚本钩子后，本机将执行数据目录 `hooks/*.js` 中的用户脚本（受限解释器，无文件系统/网络能力）。
> 请仅放入你信任的脚本；恶意脚本可能窃取被传入的只读数据（标题、时间、归档内容等）。
> 该功能默认关闭，需手动开启。

### 6.3 移动端局域网访问警告

> ⚠️ 移动端只读视图将数据以网页形式暴露在本机局域网端口，**切勿将端口映射到公网 / 内网穿透**。
> 密码经 HTTP 明文传输，仅用于局域网内轻量防护，不构成强安全。该功能默认关闭。
