# 脚本钩子使用说明（Phase 3 / V2.0，应用版本 0.4.0）

## 机制

- 钩子脚本放在**用户数据目录**下的 `hooks/` 子目录中（例如 `%APPDATA%\个人日程管理\hooks\`，
  或自定义数据目录的 `hooks/` 下）。文件名必须以 `.js` 结尾。
- 每个脚本可声明一个或多个生命周期钩子函数：

  | 钩子 | 触发时机 | 入参（只读 JSON 字符串） |
  | --- | --- | --- |
  | `on_event_saved(payload)` | 事件保存后 | 事件对象 |
  | `on_archive_entry_add(payload)` | 归档条目写入后 | 归档条目 |
  | `on_candidate_refresh(payload)` | 候选刷新（「现在」页加载）后 | 候选结果 |

- 钩子入参为**只读 JSON 字符串**；钩子返回一个字符串作为「导出输出」，由后端收集。
- 钩子运行在受限 JS 解释器（`boa_engine`）内，**无文件系统 / 网络 / 进程能力**，
  因此无法修改内部数据文件——这是「只做导出类场景」的强制约束。

## 安全警告

- 钩子功能**默认关闭**，须在「扩展 → 脚本钩子」页手动开启。
- 启用后，本机会执行 `hooks/*.js` 中的任意用户脚本（解释器受限，但仍是代码执行）。
  **请只放入你信任的脚本**；恶意脚本可能读取被传入的只读数据（标题、时间、归档内容等）。
- 不做复杂沙箱：本方案依赖解释器本身无 I/O 能力作为隔离边界，不等于完全安全。

## 示例

把 `on_event_saved.js` / `on_archive_entry_add.js` / `on_candidate_refresh.js` 复制到
`hooks/` 目录，然后在「扩展 → 脚本钩子」开启开关，即可在事件保存、归档、候选刷新时触发。
在「测试钩子」面板可手动运行某个钩子并查看每个脚本的返回输出。

## 类型声明

`hooks.d.ts` 提供编辑器类型提示（仅提示用，运行时按全局函数约定解析）。
